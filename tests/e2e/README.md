# Browser E2E status

E01–E15 use `@P0`; E16–E23 use `@P1`. They expand into 51 browser tests. Run `npm run test:e2e:p0`, `npm run test:e2e:p1`, or `npm run test:e2e:list`. Append `-- --list` to preview a selected priority without starting a browser.

The React frontend is implemented in `web/`. Run `npm run test:e2e:local` to start the app and local-only Emulator harness, execute these acceptance tests, and stop the services. The backend is also tested independently with Vitest and production Firestore Rules. Browser tests fail prerequisite checks instead of skipping or mocking successful saves.

The local-only harness in `support/harness.ts` implements: `/__e2e/health`, `seed`, `snapshot`, `clock`, `fault`, and `qr` at `E2E_HARNESS_URL` (default `http://127.0.0.1:4400`). Health must identify an Emulator-only `demo-` project. Seed atomically resets test data and returns deterministic QR payloads plus a replaced QR. Snapshot projects real backend records into the types in `support/data.ts`. Clock and fault controls apply to actual service execution; before-commit faults prevent a commit, after-commit faults lose its reply, hold-response faults delay its real reply, and release removes faults. Faults are injected by a loopback transport proxy before forwarding, after a real response, or while holding its reply. A dedicated test Functions bundle reads the controllable clock; test Rules are reloaded to match. Both live outside production entry points and builds.

`E2E_BASE_URL` defaults to `http://127.0.0.1:5173`. Only loopback app/harness URLs are accepted. A test-only Google sign-in adapter selects the seeded teacher with `/sign-in?e2eTeacher=...`; it must obtain a Google-provider identity from Auth Emulator and use real Firebase session persistence. Production must ignore this parameter. The camera fixture supplies QR pixels through `getUserMedia` so the actual QR reader remains under test. It uses whole-pixel modules and a fixed QR mask to avoid synthetic-image decoding artifacts. The foreground test dispatches a focus event because headless Chrome does not emit one for `bringToFront`; real window/background behavior remains a device check. The account-switch test keeps the document alive so delayed replies reach the old unmounted session. Audio playback is observed by the fixture; real audio audibility needs device checks.

Select labels are Thai while option values use the shared machine status codes. Generated sounds use WAV files. Real Google OAuth, iPhone/Android camera behavior, background/resume events, printed QR readability and the full PDF 4×5 card layout require additional device/print checks. The current PDF test checks A4 page dimensions, pagination, an embedded font and individual PNG QR decoding; it does not prove the contents or geometry of every PDF card.
